# 다했니월드(Dahandin World) 전용 개발 워크플로우 (Skill)

이 파일은 사용자와 AI가 다했니월드 프로젝트를 진행할 때 반드시 지켜야 할 **작업 방식 및 규칙**을 명시한 가이드(Skill)입니다. AI는 향후 모든 작업에서 사용자의 별도 지시가 없더라도 아래의 규칙을 기본적으로 준수해야 합니다.

## 1. 작업 관리 및 진행 방식 (Step-by-Step)
- **할 일 목록 생성:** 새로운 업데이트나 패치 지시를 받으면, 가장 먼저 지시받은 내용을 바탕으로 `task.md` (또는 체크리스트) 파일에 **할 일 목록(Task List)을 작성**합니다.
- **순차적 개발:** 모든 작업을 한 번에 처리하지 않습니다. 할 일 목록 중 **한 번에 한 가지 작업만** 진행합니다.
- **보고 및 확인(Confirm):** 하나의 작업을 완료할 때마다 사용자에게 작업 내용을 보고하고, **사용자의 확인(피드백)을 받은 후에만 다음 작업으로** 넘어갑니다.

## 2. 데이터베이스(DB) 로직 변경 규칙
- 파이어베이스(Firebase/Firestore)의 데이터 구조나 로직을 수정, 추가하는 작업이 발생할 경우, 반드시 프로젝트 내의 **DB 구조 설명 파일(`.cursorrules` 또는 `rule.md`)을 함께 업데이트**하여 최신 상태를 유지합니다.

## 3. Git 및 배포 워크플로우
- **브랜치(Branch) 생성:** 새로운 패치 작업을 시작하기 전, 안전을 위해 새로운 버전 브랜치(예: `ver1.x`)를 생성하고 체크아웃한 후 작업을 시작합니다.
- **커밋 및 푸시:** 모든 개발 목록(할 일)이 완료되고 사용자의 최종 확인이 떨어지면, 작업 내역을 커밋(Commit)하고 현재 브랜치로 푸시(Push)하여 배포합니다.
- **메인(Main) 브랜치 병합:** 배포된 사항에 이상이 없다고 사용자가 최종적으로 "확인했다"고 승인한 경우에만, `main` 브랜치로 병합(Merge)을 진행합니다.

## 4. UI/UX 및 코딩 스타일
- 기존의 React 컴포넌트 구조(Tailwind CSS)와 코드 스타일을 존중하며, 사용자 친화적이고 일관된 디자인(예: 알맞은 여백, 반응형, 자연스러운 전환 효과)을 유지합니다.
- 문제가 발생할 경우 원인을 먼저 분석하고, 여러 가지 해결 방안을 고려한 뒤 사용자에게 제안합니다.
